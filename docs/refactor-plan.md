# 改版计划：从谐音梗播客到观点播客

> 整理自 2026-10-01 和 Claude 的两次讨论。状态：**规划中，还没开始写代码**。

## 目标

把《Aaron Cat and Grace》从"三个主持人讲谐音梗"改成**我的个人观点输出网站**：

- 我读完一本书，三个 AI 角色用提问、反驳、解释的方式，把**我的**观点和理解讲出来，让人更容易消化。
- 每期发布成播客音频和完整文字稿，三个角色在网站 feed 上各发一条帖子。

## 现状：改版的起点

现有流程已经能跑通：DeepSeek 生成 JSON 剧本 → ElevenLabs 配音 → Supabase 加 React feed。

改版只需要换两样东西：

- **输入**：三个梗 → 一本书和我的批注
- **剧本 prompt**：抖包袱 → 提问、反驳、解释

剧本输出格式（`speaker` / `text` / `emotion` / `segment`）保持不变，`modules/audio_generator.py` 不用改。

## 角色重新分工

| 角色 | 原来的人设 | 在观点节目里的作用 |
|------|-----------|-------------------|
| Aaron | 20 多岁，热情，爱用网络用语 | 替听众提问："等下，这什么意思？""这跟我有什么关系？"把抽象的东西拉回日常 |
| Grace | 冷幽默，毒舌 | 反方，负责质疑："这不就是幸存者偏差吗" |
| Cat | 一只有阅历的猫，爱讲哲理 | 解释者：用比喻把观点讲透，最后升华 |

我的观点不固定由某一个角色说。如果我对作者持怀疑态度，Grace 就是我的嘴替。

## 要提防的两个问题

1. **假辩论。** AI 写对话最常见的毛病是：Grace 提个软绵绵的质疑，Cat 解释一句，Grace 就说"有道理"。反驳要是真反驳，最好来自我读书时自己的疑问。也要允许有些争论没有结论，让 Grace 赢几个回合。
2. **"我的观点"被冲淡。** 只把书丢给 AI，出来的是书的观点加 AI 自己的平均看法。流程里必须有我的输入，否则做出来的只是一篇 AI 书评。

## AI 怎么读一本长书

原则：**连贯靠结构，不靠模型的记性。**

- 装得下不等于读得好。模型对超长文本的注意力不均匀，中间部分容易被略过。一次性总结往往很泛，作者层层推进的论证会被压扁成几句口号。
- 名著还有一个隐患：模型训练时读过大量书评，可能凭印象说话而不是看原文，细节容易张冠李戴。
- 所以要像人写读书报告一样：先逐章做笔记，再列提纲，最后才写剧本。

## 完整流程

### 阶段一：自动读书、出初稿

1. **逐章提炼。** 一次只给一章，输出结构化笔记：核心主张、论据、关键例子、值得引用的原句（标章节）、可能的反驳。同时附上前面各章的论点摘要，让每章的理解接着全书走。
2. **整理全书论证地图。** 根据各章笔记，理出全书主要论点、每章怎么支撑它、哪里有矛盾或薄弱处。
3. **切分成期。** 一期只讲一到三个观点，时长约 15 分钟。一本书做成三到五期的系列。
4. **生成初稿。** 遇到需要立场的地方，AI 不替我编，而是标成"待你表态"来问我。
5. **通知我**：新稿好了，发邮件或推送。

### 阶段二：我审稿批注（约 20 分钟）

- **审文字，不审音频。** 一期 15 分钟的节目大约四五千字，读完十分钟左右，剩下十分钟批注。
- **批注分四类**：我的观点 / 改写 / 纠错 / 删除。每条可以指定"让谁说"（Aaron、Grace、Cat 或自动）。
- 回答初稿里的"待你表态"。
- 提交。

### 阶段三：自动重写和发布

6. **只重写有批注的段落，其余锁定。** 不锁的话，每轮都会动到已经满意的句子，审稿永远收不了尾。
7. **审查一遍**：对照章节笔记检查有没有歪曲原书，Grace 的反驳是不是太软，有没有冒出我没说过的立场。
8. **（待决定）快速确认**：只看因为批注而改动的句子，点一下通过。
9. **配音**：ElevenLabs，和现在一样。
10. **发布**：
    - 音频
    - 完整文字稿页面（三个角色的台词用不同颜色）
    - 三条角色帖子：Aaron 抛一个钩子问题，Grace 一句冷吐槽，Cat 一句金句

## 审稿页设计要点

- **顶部**：书名、第几期（共几期）、第几轮、还有几处待表态、预计阅读时间。
- **左侧**：按段落排列的剧本。每段顶部先写"书里的观点"，下面是三个角色的台词，用角色颜色区分。"待你表态"用醒目的黄色标出。
- **右侧**：批注列表，加一个新增批注的表单（类型、内容、让谁说）。
- **底部**：保存草稿 / 提交批注，并提示"没批注的段落提交后锁定"。
- **手机上也能用**：点一句话，从底部弹出批注框。

## 技术方案（基于现有代码）

**Supabase 新增几张表：**

- `books`：书
- `episodes`：每期节目，带状态字段
- `script_lines`：每句台词一行，带 `locked` 标记
- `annotations`：批注。字段包括类型、批注的是哪句或哪段、让谁说、第几轮

**节目状态：**

```
drafting → in_review → regenerating → awaiting_confirm → producing_audio → published
```

**代码改动：**

- 审稿页：`web/` 里的 `/admin/review/:id`
- 新增 `modules/book_reader.py`（逐章提炼、论证地图）和 `modules/outline_generator.py`（切分成期、列大纲）
- `data/jokes/` 换成 `data/books/<书名>/`，放原文、章节笔记和大纲
- 重写 `modules/script_generator.py` 的 `SYSTEM_PROMPT`：segment 改为 `intro` / `idea_1..n` / `outro`
- Python 流程改成后台程序：盯着 `episodes` 的状态变化，自动重写、配音、发布。先在 Mac 上跑，之后挪到 GitHub Actions 或一台便宜的云服务器。

## 建议的开发顺序

2. **做读书流程**，也就是阶段一的自动化。
3. **做自动配音、发布和通知。**
